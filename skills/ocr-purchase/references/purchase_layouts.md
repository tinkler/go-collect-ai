# 8 种典型供货单版式(参考)

> 解析供货单 OCR 文字时,识别"这张单据属于哪种版式"非常关键。不同版式列结构、字段位置、单位位置都不同。
> 配合 `skills/ocr-purchase/SKILL.md` 步骤 1-6 使用。

---

## 1. 印刷 A4 表格(最常见,中型批发商)

```
┌────┬────────────────┬─────────────┬──────┬─────┬───────┐
│序号│ 条码           │ 商品名称    │ 规格 │单位 │ 数量  │
├────┼────────────────┼─────────────┼──────┼─────┼───────┤
│ 1  │ 6923644254230  │ 蒙牛纯牛奶  │ 200ml│ 件  │  12   │
│ 2  │ 6923644258900  │ 蒙牛酸乳    │ 250ml│ 排  │   5   │
│ 3  │ 6925301901234  │ 加多宝凉茶  │ 310ml│ 箱  │   2   │
└────┴────────────────┴─────────────┴──────┴─────┴───────┘
供应商: 汇一商贸          日期: 2026-09-02
```

**特征**:
- 8 列结构清晰(序号/条码/名称/规格/单位/数量/进价/金额)
- 数字印刷规整,OCR 识别率高
- 数量在固定列(右起第 2 列),基本不会错位

**易错点**:
- "金额"列在最后,容易被误读为"数量"(实际上数字更大,LLM 看到 100+ 应该警觉)
- "进价"和"数量"都是数字,容易混淆(进价是 5.50/件,数量是 12)

## 2. 手写送货单(小供应商,纸 + 圆珠笔)

```
   汇一送货单  9月2号
1  6923644254230  蒙牛纯牛奶 200ml*12   件    3
2  6923644258900  蒙牛酸乳 250ml       排    5
3  6925301901234  加多宝 1.5L          箱    2
   合计 10 件
   司机: 张三
```

**特征**:
- 无表格线,OCR 必须靠 `top` 坐标分行
- 手写数字不规范(7 写成 1, 0 写成 6, 5 写成 15)
- 列分隔靠空格,容易错位

**易错点**:
- 数字"15"经常是"5"手写变体
- 数量列可能被 OCR 拆成 2 段(比如 "1 5")
- "件" 经常被 OCR 读成 "3"(形近字)
- "司机" 后面的人名不要识别成商品名

---

## 3. 电子表格截图(微信发的 Excel 截图)

```
┌─────┬──────────┬──────────┬──────────┬────┐
│行号 │ 商品编号 │ 商品名称 │ 单位     │数量│
├─────┼──────────┼──────────┼──────────┼────┤
│  1  │ 10002345 │ 可口可乐 │ 330ml*24 │ 12 │
│  2  │ 10002346 │ 雪碧     │ 330ml*24 │  6 │
│  3  │ 10002347 │ 芬达     │ 330ml*24 │  3 │
└─────┴──────────┴──────────┴──────────┴────┘
```

**特征**:
- 数字是文本格式(开头有引号, Excel 截图中看是 0xx 形式)
- "商品编号" 可能是 6-8 位纯数字,**不是 barcode**
- 数量是整数,OCR 容易读对

**易错点**:
- 不要把"商品编号"误读成"barcode"
- 这种表的"单位"经常是空的(只在商品名里含 330ml*24)

## 4. 微信/钉钉文字清单(无表格)

```
汇一今日到货清单:
1) 可口可乐 330ml*24 12件
2) 雪碧 330ml*24 6件
3) 芬达橙味 330ml*24 3件
4) 美汁源果粒橙 1.5L*6 2箱
共 23 件
```

**特征**:
- 完全没有 barcode(只能靠商品名匹配)
- 单位在数量后(中文)
- 用序号 + 括号分行

**易错点**:
- 数量 12 是行尾的整数,要看到 "件" 才确认
- 雪碧和芬达商品名相近,容易混淆(靠 brand hints)
- 最后一行的"共 23 件"是合计,要 skip

---

## 5. 超市内送小票(热敏纸,小)

```
  汇一超市
2026-09-02 14:32
─────────────────
可口可乐 330ml     x2
雪碧 330ml         x1
芬达橙味 330ml     x3
─────────────────
合计: 6
```

**特征**:
- 数量用 "x2" 形式
- 没 barcode(只能靠商品名)
- 数字小,OCR 识别率低

**易错点**:
- "x2" 里的 "x" 是字母,不是乘号
- "x2" 容易被读成 "xZ" / "X2" / "×2"

## 6. 大型经销商 ERP 导出(长表格,多 SKU)

```
  订单号: PO20260902001  供应商: 汇一商贸
  序号  条码          商品名称            规格         单位  数量  单价  金额
  ────────────────────────────────────────────────────────────────────
   1   6923644254230 蒙牛纯牛奶全脂       200ml*1*12  件   12   5.50  66.00
   2   6923644258900 蒙牛酸乳原味         250ml*1*24  排    5   8.00  40.00
   ... (省略 50 行) ...
  100  6925301987654 加多宝凉茶           310ml*1*24  箱    2  18.00  36.00
  ────────────────────────────────────────────────────────────────────
  合计: 100 项  1,250.00 元
```

**特征**:
- 列非常规整,9 列结构
- 数字精度高(单价带小数点)
- 表格线清晰

**易错点**:
- "金额"列(末列)数字远大于"数量",LLM 必须看清楚
- 长表格中段(50 行以后)容易有 OCR 跳行
- 规格 "200ml*1*12" 看似数字多但不是数量

## 7. 半印刷半手写混合(常见于乡镇批发商)

```
─────────────────
  汇一 9/2 到货
─────────────────
  [印刷部分]
  6923644254230  蒙牛纯牛奶  件  12
  6923644258900  蒙牛酸乳    排   5
  [手写补充]
  加多宝 1.5L*6  2 箱  ← 圆珠笔
  雪碧 330ml*24  6 排  ← 圆珠笔
  合计 25
─────────────────
```

**特征**:
- 印刷部分识别率高
- 手写补充行识别率低,需要靠商品名 hints
- 两种字体混在一起,LLM 要分别处理

**易错点**:
- 手写行的"件/排/箱"经常被 OCR 读成数字
- 手写数字"6"和印刷数字"6"是不同字体

## 8. PDF 转图片(页数多,有页眉页脚)

```
  汇一商贸 - 9 月供货单 - 共 3 页 第 1 页
  ═══════════════════════════════════════
  6923644254230  蒙牛纯牛奶  件  12
  6923644258900  蒙牛酸乳    排   5
  6925301901234  加多宝凉茶  箱   2
  ═══════════════════════════════════════
  小计: 19 件
  
  汇一商贸 - 9 月供货单 - 共 3 页 第 2 页
  ...
```

**特征**:
- 页眉有供应商名 + 日期 + 页码
- 页脚有"小计"
- 跨页时同一条可能被切两半

**易错点**:
- 页眉的"汇一"可能被识别成商品
- "小计" 行要 skip
- 跨页切分时,第一条商品可能被切到上一页末尾

## 版式识别决策表

LLM 看到 OCR 文字时,先识别属于哪种版式:

| 特征 | 推断版式 |
|---|---|
| 表格线清晰 + 8 列 | #1 印刷 A4 |
| 圆珠笔 + 无表格 | #2 手写 |
| 截图风格 + 边框 | #3 电子表格 |
| 序号 + ) 形式 | #4 文字清单 |
| "x数字" 形式 | #5 小票 |
| 9 列 + 印刷精美 | #6 ERP 导出 |
| 印刷 + 手写混合 | #7 混合 |
| 页眉页脚 + 页码 | #8 PDF 转图 |

**但** — 不需要显式告诉 LLM "这是版式 N",只要在 strategy_body 里描述该 supplier 常用版式,LLM 自己会适配。

# 静默升级规则

> **作用**:LLM 看到 `restock_task.priority` 自动从 P2→P1→P0 时,要知道为什么。
> 静默升级 = 系统自动改 priority 字段,不再"老板看到才改"。

## 升级矩阵

| 当前优先级 | 静默时间 | 升到 | 推送给 |
|---|---|---|---|
| P3 | 不升级 | - | 采购经理看板 |
| P2 | 24 小时无响应 | P1 | 卖场主管 + 老板抄送 |
| P1 | 12 小时无响应 | P0 | 卖场主管 + 老板 + 办公室 |
| P0 | 30 分钟无响应 | (推老板) | 老板(主) |

## "无响应"的定义

任务处于以下任一状态视为"无响应":
- 状态 = `open`,无 `acked_by`
- 状态 = `acknowledged`,无 `settled_at`,超过 SLA

## 不升级的特殊情况

- **季节性商品的节后**: 自动 P3,不再升级
- **临期品**(< 7 天到期): 直接关单,标 `cancelled`,不升级
- **滞销品**(30 天销 < 1): 标 P3 不动
- **黑名单供应商**: 标 `cancelled`,不升级
- **手动 ack 但未关闭**: 升级暂停,等员工 settle

## LLM 解释模板

```
这条 P2 自动升到 P1 了,原因是:
- 24 小时前系统推送了 P2 任务
- 状态还是 open,没人 ack
- 库存继续消耗,days_until_stockout 从 1.8 降到 1.2
按规则自动升 P1,推送给卖场主管 + 老板。
```

## 编辑权限

老板和运营经理可调时间阈值(比如 P1 升 P0 改成 8 小时)。改完即生效。

# Restock 优先级语义(P0 / P1 / P2 / P3)

> **作用**:LLM 看到 `restock_task.priority` 字段时,必须看这张表才能正确解释给员工听。
>
> **触发公式**(可改,见 escalation_rules.md):
> ```
> days_until_stockout = inv_snapshot / daily_avg
>   < 0.5 → P0
>   < 1.5 → P1
>   < 3   → P2
>   ≥ 3   → P3
> ```

## P0 — 立即处理

| 维度 | 内容 |
|---|---|
| 中文标签 | 🔴 立即处理 |
| 含义 | 库存撑不到半天,马上要断货 |
| 响应 SLA | < 30 分钟 |
| 推送给 | 卖场主管(主) + 老板(抄送) |
| 按钮 | "立即处理" / "已联系供应商" |
| 升级 | 30 分钟无响应 → 推老板群 |

## P1 — 2 小时内处理

| 维度 | 内容 |
|---|---|
| 中文标签 | 🟠 2 小时内 |
| 含义 | 当天会断货但还有一点时间 |
| 响应 SLA | < 2 小时 |
| 推送给 | 卖场主管(主) |
| 按钮 | "准备补货单" / "联系供应商" |
| 升级 | 2 小时无响应 → 升 P0 |

## P2 — 今日处理

| 维度 | 内容 |
|---|---|
| 中文标签 | 🟡 今日 |
| 含义 | 1-3 天内会断货,今日可以处理 |
| 响应 SLA | 当日内 |
| 推送给 | 卖场主管(主) |
| 按钮 | "加入今日补货" / "明天处理" |
| 升级 | 24 小时无响应 → 升 P1 |

## P3 — 预防性

| 维度 | 内容 |
|---|---|
| 中文标签 | 🟢 预防 |
| 含义 | 库存充足但提前提醒(系统检测到趋势) |
| 响应 SLA | 无 SLA,只是建议 |
| 推送给 | 采购经理(看板) |
| 按钮 | "已加入下周计划" / "暂不处理" |
| 升级 | 不升级 |

## 不升级的特殊情况

| 情况 | 处理 |
|---|---|
| 季节性商品(雪糕/月饼) | 优先级可下调一档(节后才卖) |
| 临期商品(< 7 天到期) | 优先级**下调**到 P3(不应该补货了) |
| 滞销商品(连续 30 天 < 1 件) | 优先级直接 P3,不再升级 |
| 黑名单供应商的商品 | 不进补货单,优先级 N/A |

## 编辑权限

老板和运营经理可调阈值 / 加新等级(比如"P4 极低")。改完即生效。
